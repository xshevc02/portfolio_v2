1

Context

A reading app that feels personal, not like a database.

Pockland is a personal book tracking and reading companion app. It helps readers organize books, track reading progress, manage wishlists and custom shelves, view book details, add feedback, and discover books through Open Library and Google Books.

The project started from a simple product need: book tracking often gets scattered across notes, Notion databases, screenshots, wishlists, and memory. I wanted the experience to feel lightweight, visual, and personal while still supporting real product behavior.

  • Track reading progress and reading states.
  • Organize books into wishlist, finished, reading, and custom shelves.
  • Search and discover books through external APIs.
  • Support account-based syncing across sessions.

2

Research

Competitor reviews turned vague ideas into specific feature requirements.

Before starting the design, I looked at existing book-tracking apps such as Goodreads and checked reader feedback from App Store reviews. This helped me separate “nice to have” ideas from real user frustrations people were already expressing in similar products.

Two repeated needs influenced the product scope directly: the ability to add books manually when search, barcode, or cover recognition cannot find a title, and a better way to track audiobooks where progress is measured by time or duration rather than page count.

What it changed

Added manual book entry as a fallback for books missing from external databases.
Included audiobook progress tracking so users are not forced into page-based progress.
Considered more flexible rating behavior after seeing requests for 0.5-star ratings.
Used competitor feedback as an input for product decisions before moving into UI design.

3

Product scope

From mobile-first screens to a real responsive product.

The app evolved around four main areas: Home, Feed, Shelves, and Profile. Home surfaces currently reading books, wishlist suggestions, trending books, and an award shelf. Shelves support reading states and custom organization, while Profile brings together user information, reading activity, and a reading calendar.

The product needed to behave like a real app rather than a static concept. That meant authentication, synced personal data, book status changes, manual book creation, audiobook progress tracking, 0.5-star rating support, custom shelf actions, search behavior, book detail pages, and responsive layouts across mobile and desktop.

Home Feed Shelves Profile
  • Fixed navigation between Home, Feed, Shelves, and Profile.
  • Book detail and author pages with simplified metadata.
  • Inline shelf rename and delete actions.
  • Clear confirmation copy explaining that deleting a shelf does not delete the books.

4

AI-assisted workflow

AI made the app clickable fast, but it did not replace product direction.

AI was useful because it let me move quickly from a product idea into a clickable, deployable prototype. It helped generate screens, interaction states, responsive layouts, authentication flows, search behavior, shelves, progress tracking, and synced user data without treating the project as a static mockup.

The tradeoff became visible very quickly: because I skipped a low-fidelity mockup at the start, the AI filled too many product and layout gaps by itself. It generated components that looked complete but had no real user value, invented page structures I did not actually need, and created extra cleanup work that a simple Figma sketch could have prevented.

The biggest process lesson was that AI implementation works faster when the designer first defines the page logic: what each screen contains, which components are required, where they should live, and how the mobile and desktop versions should differ.

A rough mockup would have reduced the number of prompts spent on basic placement, hierarchy, and component logic.

The strongest results came after I gave specific design critique instead of accepting the first generated UI.

I pushed the interface toward reused components instead of letting every page introduce a new pattern.

AI accelerated implementation, but the final quality came from repeated review, testing, and design judgment.

6

UX decisions

Repairing the gap between mobile polish and desktop reality.

Several UX decisions came from repeatedly testing the live prototype on different screen sizes. At first I focused mostly on the mobile experience; once that felt cleaner, the desktop version exposed a second layer of problems: stretched cards, awkward empty space, oversized progress elements, and layouts that looked like mobile screens simply widened across a larger viewport.

This became one of the most important iteration areas. I had to specify how objects should reflow, which cards deserved more space, where navigation should sit, and which mobile patterns needed a separate desktop treatment instead of a larger version of the same layout.

I refined the app around consistency: reusable vertical book cards, compact rating badges, direct status selectors on cards, clearer shelves, and search behavior that did not interrupt the mobile keyboard.

  • Mobile-first structure adapted into a more spacious desktop layout.
  • Separate reading states for Reading, Wishlist, Finished, and custom shelves.
  • Manual book entry, audiobook progress tracking, and 0.5-star rating support added as research-backed product decisions.
  • Google Books fallback added when Open Library could not find a title.
  • Currently Reading card redesigned to respond better to screen height and width.
7Feedback updates · done

Turning feedback into implemented UX improvements.

After reviewing the working prototype, I separated feedback that directly affected everyday usability from broader product ideas. The UX-impacting changes were prioritized first, especially areas that made personal reading history easier to scan and the interface easier to adapt to different readers.

The following feedback items were treated as completed updates in the current iteration rather than left as open backlog notes.

Profile: show best and worst books read by the user to make personal reading history easier to scan.
Customization: add settings for font size, preferred language, preferred writer countries, all four seasonal themes, and trigger moments that can be used as filters or hidden-by-default descriptions.
8Future ideas · backlog

Keeping larger product ideas for future feature exploration.

The remaining feedback is intentionally framed as future product direction. These ideas could make Pockland richer over time, but they are not required to resolve the core usability problems found during the current prototype review.

This keeps the case study honest: the immediate experience issues were addressed, while larger ecosystem features stay available for later prioritization, testing, and scope decisions.

Social discovery: add book clubs, friends in Feed, and recommendations that preserve who suggested a book or which post it came from.

Search and discovery: automatically add searched books to wishlist, add filters by language and writer country, and recommend books based on similar readers or fandoms.

Mobile UX: make the Back action return inside the app instead of leaving through browser history.

Book editing: support inline feedback creation/editing, total page count editing, and total reading or listening time editing.

Shelves and layout: add custom shelf cover images, direct add-to-shelf actions, automatic source attribution from posts, full-width desktop feed cards, and separate desktop Currently Reading cards.

9

Outcome

A working prototype shaped by many rounds of critique.

The final result is a functional responsive web app with authentication, synced personal data, book discovery, reading progress, custom shelves, and polished UI patterns.

Compared to the early generated versions, the final app has better navigation, cleaner book cards, improved shelf management, clearer detail pages, more reliable search behavior, and a stronger mobile-to-desktop experience. AI accelerated prototyping, but the quality came from repeated critique, testing, and design direction.

  • Designed a mobile-first reading app and adapted it into a responsive desktop experience.
  • Created core flows for adding books, tracking progress, managing shelves, and viewing book details.
  • Integrated real auth/data constraints into the product experience.
  • Used AI to accelerate prototyping while independently directing UX critique and product decisions.
